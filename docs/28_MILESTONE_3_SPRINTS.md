# 28 — Milestone 3 Sprints (Experience Layer)

Mirrors [16_ENGINEERING_SPRINTS.md](16_ENGINEERING_SPRINTS.md)'s format for Milestone 2, scoped to Milestone 3. Built on Engine v1.0 (`v1.0.0-engine`, [ENGINE_CHANGELOG.md](../ENGINE_CHANGELOG.md)), now frozen: every sprint below extends the engine through interfaces, registries, plugins, composition, and adapters — no engine rewrites, no breaking changes. If a feature seems to need an engine change, the sprint's own review must first prove extension is impossible before any ADR proposing one gets written.

**Implementation philosophy, stated in the brief and worth repeating here**: users should never notice the engine — only the delight it enables. Every sprint must produce something a user can touch, interact with, and remember. Motion, lighting, micro-interactions, sound, storytelling, and delight are first-class features, not polish bolted on at the end — the Creative Budget rule that started in Milestone 2 continues here, but the bar moves from "did engineering excellence increase" (assumed now) to "did emotional impact increase."

Documentation follows working code, same as Milestone 2 from Sprint 2.1 onward — this doc's entries below Sprint 3.1 stay sketch-level until their own sprint starts.

**Two real bugs found and fixed during manual verification, not shipped**: (1) the customizer panel's own internal scroll can carry the whole window down far enough to hide the fixed navbar — `AddToCartButton` now snaps the window back to the top before measuring the fly-animation's target, so the cart icon is always a real, visible destination regardless of scroll position. (2) every `Button` rendered as a `<Link>` in the new cart UI was missing `nativeButton={false}` (the established convention `DrinkDetailDialog.tsx`/`HeroCopy.tsx` already use for exactly this), producing a real Base UI console warning on every page load — fixed across all 7 occurrences.

**A real regression found and fixed during the full e2e regression run**: adding `CartAnnouncer` to the global navbar meant `/customize` and `/concierge` could now have *two* simultaneous `role="status"` live regions, breaking two pre-existing Sprint 3.3/3.5 e2e tests that assumed only one existed. Fixed by giving every announcer (`IngredientAnnouncer`, `RecommendationAnnouncer`, `CartAnnouncer`) a distinguishing `aria-label` — a real, correct accessibility improvement for screen-reader users with multiple simultaneous live regions, not just a test-targeting convenience — and updating the two tests to target their own region by name.

**A real, deliberate discipline this sprint practiced repeatedly**: several genuine findings from the audit were investigated and then explicitly *not* turned into code changes — the Hero/Customizer/Concierge camera-framing clip (real, but changing the project's single most-reviewed camera preset without dedicated visual-QA time was judged too risky), the unused `--spacing-section` design tokens (real, but the token values don't match any route's already-converged spacing, so wiring them in would be a real, unverified layout shift across most of the app), and the drag-vs-scroll-camera interaction conflict on `/story` (real, flagged since the Architecture Freeze, but a UX design decision, not a mechanical fix). Each is documented, with the reasoning, in the RC1 report's Risk Register and Technical Debt sections — "if any existing implementation appears wrong: STOP, document the issue," this sprint's own explicit instruction, applied for real rather than as a formality.
