# 21 — Test Strategy

Sprint 0 deliverable. What gets tested, how, and with which tool, per manager — decided now so Sprint 2.6 (where [16_ENGINEERING_SPRINTS.md](16_ENGINEERING_SPRINTS.md) flags the Vitest/Playwright installation decision) executes against a plan instead of improvising one. Stack stays as [11_TESTING_QA.md](11_TESTING_QA.md) already decided: **Vitest + React Testing Library** for unit/component, **Playwright** for e2e/visual/accessibility flows. Nothing here is installed yet — this is the target, not a claim that tests exist.

## Reading this table

Not every manager needs all five categories — a pure registry has no meaningful "visual test," and forcing one would be exactly the coverage-number-chasing [11_TESTING_QA.md](11_TESTING_QA.md) already rejects. "—" means genuinely not applicable, not "skipped."

## What stays manual, deliberately

Full-experience judgment calls — "does the steam actually look convincing," "does the day/night transition feel right" — are Creative Director Review territory ([09_CREATIVE_DIRECTOR_REVIEW.md](09_CREATIVE_DIRECTOR_REVIEW.md)), not something a Playwright assertion should attempt to encode as pass/fail. Automated visual regression here catches *unintended drift* (a color token change accidentally shifting the hero's lighting), not *quality* — those are different jobs, and conflating them was already rejected once in [11_TESTING_QA.md](11_TESTING_QA.md)'s "why manual checks count as QA" section.
